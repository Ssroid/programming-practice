# 디자인 패턴 학습 노트 (Java)

자주 쓰이는 GoF 디자인 패턴 15개를 초보자용 예제로 정리했습니다.
각 패턴 폴더에는 `Main패턴이름.java` 실행 파일이 있습니다. IntelliJ에서 ▶ 버튼으로 바로 실행해 보세요.

## 📂 읽는 순서 (패턴마다 공통)
1. **`Main패턴이름.java`의 `main()` 메서드 주석**을 먼저 읽기. "문제 → 해결 → 역할 → 장단점 → 실무 예시"가 정리되어 있습니다. (아래 표의 "시작 파일")
2. **인터페이스(또는 추상 클래스)** 읽기. 이 패턴에서 맡은 역할, 왜 인터페이스가 필요한지, 추상화하지 않으면 어떤 문제가 생기는지 설명되어 있습니다.
3. **나머지 역할별 파일**을 하나씩 읽기. 각 파일 맨 위에 `[역할: ...]`이 적혀 있습니다.
4. **`Main패턴이름.java` 실행**. 출력 결과와 코드를 번갈아 보며 흐름을 따라가 보세요.

## 🧱 생성 패턴 (Creational): 객체를 "어떻게 만들까?"

| 패턴 | 예시 | 핵심 한 줄 | 시작 파일 |
|---|---|---|---|
| 싱글톤 | 앱 설정 관리자 | 객체를 딱 1개만 만들어 공유 | `creational/singleton/MainSingleton.java` |
| 팩토리 메서드 | 커피 머신 | 무엇을 `new` 할지 자식 클래스가 결정 | `creational/factorymethod/MainFactoryMethod.java` |
| 추상 팩토리 | 모던/클래식 가구 | 어울리는 객체들을 세트로 생성 | `creational/abstractfactory/MainAbstractFactory.java` |
| 빌더 | 햄버거 주문 | 옵션 많은 객체를 단계별로 조립 | `creational/builder/MainBuilder.java` |
| 프로토타입 | 보고서 템플릿 | 기존 객체를 복사해서 생성 | `creational/prototype/MainPrototype.java` |

## 🔗 구조 패턴 (Structural): 객체를 "어떻게 조합할까?"

| 패턴 | 예시 | 핵심 한 줄 | 시작 파일 |
|---|---|---|---|
| 어댑터 | 110V → 220V 돼지코 | 안 맞는 인터페이스를 변환기로 연결 | `structural/adapter/MainAdapter.java` |
| 데코레이터 | 커피 토핑 | 객체를 겹겹이 감싸 기능 추가 | `structural/decorator/MainDecorator.java` |
| 프록시 | 이미지 지연 로딩 | 대리인이 진짜 객체 접근을 제어 | `structural/proxy/MainProxy.java` |
| 퍼사드 | 홈시어터 원버튼 | 복잡한 기능을 간단한 창구 하나로 | `structural/facade/MainFacade.java` |
| 컴포지트 | 폴더와 파일 | 단일 객체와 묶음을 똑같이 다루기 | `structural/composite/MainComposite.java` |

## 🤝 행위 패턴 (Behavioral): 객체끼리 "어떻게 협력할까?"

| 패턴 | 예시 | 핵심 한 줄 | 시작 파일 |
|---|---|---|---|
| 전략 | 결제 수단 | 알고리즘을 갈아 끼우기 | `behavioral/strategy/MainStrategy.java` |
| 옵저버 | 유튜브 구독 알림 | 상태 변화를 구독자들에게 자동 통보 | `behavioral/observer/MainObserver.java` |
| 템플릿 메서드 | 커피/홍차 만들기 | 순서는 부모가, 세부 단계는 자식이 | `behavioral/templatemethod/MainTemplateMethod.java` |
| 커맨드 | 스마트 리모컨 + 실행 취소 | 요청을 객체로 만들어 저장/취소 | `behavioral/command/MainCommand.java` |
| 상태 | 자판기 | 상태 객체에 따라 행동이 바뀜 | `behavioral/state/MainState.java` |

## 🎯 추천 학습 순서 (쉬운 것 → 어려운 것)
1. **싱글톤**: 가장 단순합니다. `private` 생성자와 `static`을 이해하는 연습이 됩니다.
2. **전략**: 인터페이스와 다형성을 활용하는 가장 기본적인 패턴입니다. 이것만 이해해도 절반은 됩니다.
3. **템플릿 메서드**: 상속과 `abstract`를 활용하는 기본 패턴입니다.
4. **팩토리 메서드**: 2번과 3번의 개념을 합친 형태입니다.
5. **옵저버, 빌더, 퍼사드, 어댑터**: 실무에서 매일 보는 패턴들입니다.
6. **데코레이터, 프록시, 컴포지트**: "감싸기" 구조에 익숙해지는 단계입니다.
7. **추상 팩토리, 커맨드, 상태, 프로토타입**: 마무리 단계입니다.

## 🤔 헷갈리는 패턴 비교

| 비교 | 차이점 |
|---|---|
| 팩토리 메서드 vs 추상 팩토리 | 제품 **1종류**를 상속으로 생성 vs 관련 제품 **세트**를 객체로 생성 |
| 전략 vs 상태 | 전략은 **외부에서** 골라 넣음 vs 상태는 **스스로** 다음 상태로 전환 |
| 전략 vs 템플릿 메서드 | **객체 조합**으로 전체 교체 vs **상속**으로 일부 단계만 교체 |
| 데코레이터 vs 프록시 | 기능 **추가**가 목적 vs 접근 **제어**가 목적 (구조는 비슷) |
| 어댑터 vs 퍼사드 | 인터페이스를 **변환** vs 여러 인터페이스를 **단순화** |

## 💡 모든 패턴을 관통하는 핵심 원칙
- **인터페이스에 의존하라**: 구체 클래스(`new Americano()`) 대신 인터페이스(`Coffee`)를 사용합니다.
- **변하는 것과 변하지 않는 것을 분리하라**: 바뀌는 부분만 별도 클래스로 빼냅니다.
- **OCP (개방-폐쇄 원칙)**: 새 기능을 추가할 때 기존 코드를 수정하지 않고 새 클래스를 추가합니다.
- **상속보다 조합(Composition)**: 필드로 다른 객체를 품어서 사용합니다. (데코레이터, 전략, 어댑터 등)
